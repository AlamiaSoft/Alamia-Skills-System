# Product Discovery

## Purpose
Validate the user problem, target segment, value hypothesis, feasibility and MVP boundary.

## Activation
Validate the user problem, target segment, value hypothesis, feasibility and MVP boundary.

## Inputs
Product idea; user/customer evidence; business objective; constraints; assumptions.

## Procedure
1. Define the user, context, job-to-be-done and pain point.
2. Separate observed evidence, stakeholder opinion and untested assumptions with source/confidence.
3. Map alternatives and workarounds; assess differentiation without unsupported market claims.
4. Assess feasibility, dependencies, regulation, distribution, cost and support burden.
5. Design cheap validation experiments with measurable pass/fail criteria.
6. Define personas/use cases, MVP boundary, non-goals and success outcomes.

## Outputs
Discovery brief; evidence/assumptions register; use cases; feasibility/risk assessment; MVP scope; validation plan.

## Quality checks
- [ ] Problem and target user are explicit; evidence is separated from assumptions; MVP is testable.
- [ ] Work is traceable to the requested scope and project standards.
- [ ] Relevant project knowledge and documentation are updated.

## Boundaries
Never fabricate interviews, market data, demand or competitor facts. Escalate regulated-market questions for specialist review.
