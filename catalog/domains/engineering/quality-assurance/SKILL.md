# Quality Assurance

## Purpose
Create and execute test strategy, acceptance verification, regression and release validation.

## Activation
Create and execute test strategy, acceptance verification, regression and release validation.

## Inputs
Requirements; acceptance criteria; architecture; test commands; environments; test data; change set.

## Procedure
1. Map requirements and risks to test levels and assertions.
2. Run focused tests before broader suites.
3. Cover unit, feature, integration, contract, E2E, regression and migrations as appropriate.
4. Test roles, permissions, tenant isolation, invalid inputs, retries and recovery.
5. Include browser/device, accessibility, localization and performance checks where relevant.
6. Record exact commands, environment, counts, failures, skips and flaky tests.
7. Triage defects and retest fixes.

## Outputs
Test plan; traceability; execution report; defect register; acceptance evidence.

## Quality checks
- [ ] Blocking criteria have passing evidence; skipped/flaky tests are disclosed; test setup is reproducible.
- [ ] Work is traceable to the requested scope and project standards.
- [ ] Relevant project knowledge and documentation are updated.

## Boundaries
Never fabricate results or suppress failures. Coverage alone does not prove correctness.
