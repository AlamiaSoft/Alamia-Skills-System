# UX/UI Engineering

## Purpose
Design user journeys, information architecture, responsive interfaces, design systems and accessibility behavior.

## Activation
Design user journeys, information architecture, responsive interfaces, design systems and accessibility behavior.

## Inputs
PRD; personas; workflows; brand constraints; target platforms; technical constraints.

## Procedure
1. Map journeys, navigation and information architecture.
2. Define roles, onboarding, empty/loading/error/offline/permission/success states.
3. Specify design tokens, typography, spacing, reusable components and interactions.
4. Design responsive behavior using realistic content and data density.
5. Apply semantic structure, keyboard navigation, focus, contrast and assistive-technology support.
6. Validate journeys against acceptance criteria and obtain design/product approval.

## Outputs
User flows; wireframes/prototypes; design system; screen states; responsive rules; accessibility notes.

## Quality checks
- [ ] Critical journeys include edge states; designs are consistent, accessible and implementable.
- [ ] Work is traceable to the requested scope and project standards.
- [ ] Relevant project knowledge and documentation are updated.

## Boundaries
A polished screenshot is not a complete interaction design. Do not ignore accessibility or invent brand assets.
