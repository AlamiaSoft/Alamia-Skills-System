# Frontend Engineering

## Purpose
Implement web/PWA interfaces, client state, forms, navigation, responsive behavior and API integration.

## Activation
Implement web/PWA interfaces, client state, forms, navigation, responsive behavior and API integration.

## Inputs
Approved UX/UI; API contracts; design tokens; supported browsers/devices; accessibility requirements.

## Procedure
1. Inspect routes, state/data-fetching patterns and shared components.
2. Build reusable components with minimal duplicated state.
3. Handle loading, empty, error, offline, validation, permission and success states.
4. Use client validation for usability and server validation for authority.
5. Implement responsive, semantic and keyboard-accessible behavior.
6. Handle API errors/auth expiry without hiding failures; test critical journeys and viewports.

## Outputs
Responsive UI; reusable components; state/API integration; accessibility behavior; UI tests.

## Quality checks
- [ ] Critical flows work at target viewports; keyboard/focus and error states are verified.
- [ ] Work is traceable to the requested scope and project standards.
- [ ] Relevant project knowledge and documentation are updated.

## Boundaries
Client validation is not security. Avoid unnecessary dependencies and placeholder interactions.
