# Engineering Governance

## Purpose
Establish engineering standards, Git/PR practices, Definition of Done, ownership, quality gates and agent approval boundaries.

## Activation
Establish engineering standards, Git/PR practices, Definition of Done, ownership, quality gates and agent approval boundaries.

## Inputs
Team roles; repository policy; CI; risk profile; compliance constraints; delivery model.

## Procedure
1. Define coding, testing, documentation, security and review standards proportionate to risk.
2. Establish branching, commits, PR size, ownership, review and merge policy.
3. Define Definition of Ready/Done and blocking versus advisory gates.
4. Map approvals for migrations, secrets, production, publishing, spending and external effects.
5. Define agent permissions, escalation, evidence and status vocabulary.
6. Align standards with CI and repository protections.
7. Record exceptions with owner, rationale and expiry; retire stale rules.

## Outputs
Engineering handbook; Definition of Ready/Done; review rules; quality-gate and approval matrices; exception register.

## Quality checks
- [ ] Rules are actionable and consistent with repository settings; human approval boundaries are explicit.
- [ ] Work is traceable to the requested scope and project standards.
- [ ] Relevant project knowledge and documentation are updated.

## Boundaries
Avoid governance theatre. Do not claim policy is enforced when only documented; do not weaken controls for one task.
